## Scope and execution guardrails

- Reports in these folders remain historical source/build/public evidence; this audit does not refresh their runtime identity or claim that any script passes on the current build.
- Do not run `three-maths` or Shadow `rehearsal.cjs` against retained profiles: both contain unconditional `localStorage.removeItem` calls, and Shadow removes the shared little-game map, not just its own row.
- Do not run full matrices just to obtain an integration smoke. They complete many authored missions and award state. No inspected retained-game harness exposes a one-mission/one-level CLI option; `QA_GAME` selects a game in Trace but still runs its whole scripted route.
- The minimal safe pattern is a separately bounded callback on the already-leased, namespaced QA page: normal home/profile navigation, choose one visible authored prompt, make at most one wrong attempt where useful, solve one representative action, inspect held feedback, return through the actual parent control, reload, and compare before/after raw-key hashes. Do not clear or write seeded values. If the action naturally changes saved progress, document the one allowed key and retain sibling/other-game keys unchanged.
- Batch 2 has no retained executable in its evidence folder. Pair harnesses in other folders are full pair acceptance matrices, not substitutes for a bounded retained-lane smoke.
