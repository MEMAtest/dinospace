## Current game design to retain

### Fire Truck Rescue

- Five levels contain 3, 4, 5, 5, and 5 rounds. Per-round fire counts are `1,1,2`; `1,2,2,3`; `2,2,3,3,3`; `3,3,4,4,5`; and `4,4,5,5,6`. Askia starts at Level 1; Amari's existing age floor is Level 3.
- The child aims water at a fire and holds for about 1.2 seconds. The short 350 ms tap spray deliberately does not extinguish one. A live remaining-fire counter and spray stream already teach aim and sustained action.
- Keep the authored six fire/window locations and responsive scene. The existing `fire-house.webp`, `rescue-firetruck.webp`, and `rescue-flame.webp` are coherent, polished assets; smoke has an SVG fallback. `fire-house.webp` is 941×1672 (approximately 9:16), and the scene's `56.25dvh` width is matched to that actual ratio; the older 4:5 image brief should not be used to rescale it. The photographed house is static, so the source's fallback-only `HOUSE_COLOURS` variation does not appear with the current raster house. Do not replace the working fire scene or generate replacement fire art for this pair.
- Current aim is pointer-only (`role="application"`); it has no keyboard target action or readable hold-progress cue. Empty-scene spraying gives no visible correction. A hidden tab/long frame gap can advance the extinguish meter because elapsed frame time is unbounded and a captured hold may stay active. The game does not report hint/wrong-attempt attribution, and the legacy shell can auto-advance before a child reads the result.

### Ladder Rescue

- Five levels retain the current floor/round progression: Level 1 has 2 floors/3 rounds; Level 2 has 3/4; Level 3 has 3/5 and introduces floor-number prompts; Levels 4 and 5 have 4/5 and 5/5. Amari starts at Level 3.
- Each scene assigns animals to distinct floors, prompts for an animal or a spoken floor number, raises the animated ladder, then carries the animal to safety. The floor controls are actual named buttons and already support keyboard activation.
- The building, roof, windows, SVG truck and ladder animation are functional. The five image-brief sprites (`animal-kitten`, `animal-puppy`, `animal-bunny`, `animal-chick`, `animal-panda`), `firetruck-no-ladder.webp`, and `bg-ladder.webp` are absent. Animals currently use emoji and the truck uses the inline SVG fallback. Root owns a scoped six-file visual improvement: five transparent animal portraits and one no-ladder truck at lazy public paths under `public/art/rescue-animals-v2/` (measured runtime total under 250 KB). Integrate those only if the reviewed assets land; preserve emoji/SVG fallbacks and do not alter the shared `FireTruck` or eager `littleArt` import.
- Animal order and target floor are randomized and held in component state within a round, but are not scheduled to avoid repetitive targets across plays. A wrong floor shakes briefly and speaks a generic retry, then a delayed prompt can overlap a later rescue. The ladder animation uses an untracked requestAnimationFrame loop; the `ladder` state is not set synchronously before the first frame, so rapid correct taps can schedule duplicate speech/completion timers. The current completion callback defaults to first-try/independent even after a wrong answer or a visible HandHint.

The current exact narration is already packaged: Fire's intro/start/done and number clips 1–6; Ladder's intro/wrong, all five animal prompt/success pairs, and floor prompts 1–5. The audit resolved all 9 Fire and 17 Ladder lines with `getOfflineVoiceClip`. Do not add provider/device narration, call voice/story generation, or voice any new written guidance without a matching exact clip.

## Pair-specific contract

1. **Preserve the games.** Keep both five-level designs, the age floors, authored fire positions/counts, the Fire spray and Ladder climb animations, current sprites and fallbacks. Repair their actual interaction gaps; do not replace them with a new generic game or infer completeness from unrelated Maths/route evidence.
2. **Teach during play.** Fire must show sustained-spray progress and explain an unproductive held aim with brief visible wording such as “Keep the water on the flame.” Moving around or briefly exploring the scene is not automatically a wrong answer or a penalty. A missed aim may expose a clue and truthfully lower independence without inventing a wrong-answer mistake. Add a keyboard-accessible way to act on the same visible fire targets; pointer, touch, and keyboard routes must resolve through the same game state. Ladder must keep the animal/floor target frozen after a wrong choice, hold a readable retry clue until a later correct window is chosen, and retain named accessible floor buttons.
3. **Bound and cancel active work.** Fire stops spray on pointer up/cancel/lost capture, scene exit/blur and hidden visibility; clamp frame deltas so background time cannot extinguish fires. Ladder locks a correct rescue synchronously, retains/cancels its animation frame and all prompt/rescue timers, and cancels a queued wrong-prompt replay when a correct action begins. Unmount/leave must not trigger stale narration or completion.
4. **Vary without changing a round's answer.** Freeze each play's run identity and each round's target set. Fire positions/counts and Ladder animals/floors must be stable through retry and vary over normal replays; Ladder's available floors/animals should cycle so no eligible floor or animal is permanently omitted. Do not seed answers, unlocks, or saved progress from QA.
5. **Hold feedback and advance explicitly.** Both games use the opt-in pair-safe shell path with a short written round recap and an explicit `Next` action. Fire recap confirms how many fires were put out; Ladder recap names the rescued animal and floor/target result. Do not replay a saved reward or issue intermediate quiet points. Keep the last round result visible before the game is saved/finished.
6. **Save the pair safely.** Reuse the existing pair-only `pairSafeProgress`/`manualNext` and `pairLittleProgress` contract; do not change default storage semantics for other little games. Only show saved completion, level availability, stickers, and reward after the whole child record is read/validated, written, and read back. A blocked write holds the exact pending result for Retry; reload and replay cannot duplicate a level/plays update or reward. Report hints/mistakes honestly (`firstAttempt`, `independent`, `hints`) so successful recovery is not falsely labeled independent. Preserve player isolation and unrelated game rows.
7. **Keep audio exact and packaged.** Use a stable parent speaker that reads current mute state for held-review audio. Continue to check `getOfflineVoiceClip` before each requested line and pass packaged-only options. New written clues/reviews stay text-only unless their exact clip is already in the manifest. Existing rescue audio is sufficient; no audio job is authorized or required.
