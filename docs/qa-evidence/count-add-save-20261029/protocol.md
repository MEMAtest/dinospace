# Count + Addition save acceptance protocol

This folder contains a bounded Playwright callback for root-owned runs against the exact built entry on the already leased `amari-targeted-contained` page. The callback receives that page; it never creates a browser, profile, context, tab or session. The runner checks the active lease, the existing profile path, exact entry URL and served asset hash before invoking it.

## Acceptance matrix

Run `run-count-add.py` separately for `390x740` and `1440x844` on the existing local preview (`http://127.0.0.1:5180`) and canonical site (`https://dinospace.netlify.app`). Supply the actual compiled `/assets/arcade-….js` entry and exact source/runtime SHA. `COUNT_ADD_FAULTS=1` is permitted only at 390x740. Preserve every report, including failures; the runner refuses report overwrite and bounds the folder at 8 MiB. It does not reset or seed app state.

The full driver enters Count the Stars and Addition Adventure through the normal Amari picker/world/catalogue, then completes all three authored chapters in their real order. For each game/chapter it records a six-question first run and a six-question lower-rated replay. Each answer is computed from the currently visible model/prompt; it does not read the hidden question queue or answer key from storage. Count’s normal run answers all six questions on the first try; its replay uses a visible wrong answer, clue and recount on question one and wrong answers on all six questions before choosing each visible correct option. Addition uses a visible wrong answer and hint on the first normal question, exercises join/split controls in the groups model where available, and answers the other five on the first try. Five independent correct Addition answers still earn the normal three-star rating. Its replay answers each of six questions incorrectly once before choosing the visible correct option. Rows record the rating earned by the visible answer/hint actions; the completion UI itself reports best progress. The replay checks that best stars and parent totals stay unchanged.

For each accepted question, the driver measures every primary task control before clicking: at least 44 by 44 CSS pixels, fully inside the current viewport, center point hit-tests to the control, and pointer events are enabled. It never scrolls a primary task control into view; the check fails when a task control is below the fold. It may scroll the secondary chapter/map controls before selecting a chapter. The driver waits at most two seconds for ordinary UI transitions, and each game/question/retry loop has a fixed small upper bound. It records partial rows before throwing so a later assertion does not erase earlier branch evidence. Screenshots are taken only on failure.

Packaged audio is exercised through the visible `Hear instructions` / `Hear question` control. The original sound preference is read from the visible sound toggle on first entry; the driver enables it only when needed and restores it before final storage comparison and on failure. A successful audio sample must play a same-origin packaged audio file and advance its playback time. Provider/API routes are blocked before app navigation and any attempted request fails acceptance.

Storage evidence is a before/after SHA-256 + byte inventory. Only the target game’s exact progress key, `amari_rewards_v2`, and the known shared Amari gameplay/sound keys may change; unchanged sibling-game and protected records must remain byte-identical. The Count key intentionally preserves its existing `amari_` + exported key double prefix. Reward receipt IDs and positive deltas must match the child progress record; the parent reward claim token must match the game namespace and receipt ID. The component passes scaled callback units (`delta * 4`) through the shared adapter; the stored claim and points increment equal the star delta. Parent `persisted: true` must precede the child claimed marker, and the Count intro reload lane confirms a committed parent claim is not paid twice before marking the natural pending receipt. Equal/lower replay may write byte-identical child data; raw-string change is not required when visible retry/readback and parent idempotency are established.

## Fault lane

At 390x740 only, the runner may arm a reversible wrapper on the exact logical localStorage key and restore the original prototype in `finally`. It uses naturally available Count and Addition queues and material results. It exercises start queue write failure/retry, held final result local write and readback failures/retry, parent receipt write/readback failures/retry, and a same-page intro reload that drains a natural pending receipt exactly once. Count's chain commits the parent token while the local marker remains pending; Addition also faults the parent write before commit on a second naturally material chapter, then verifies intro recovery and resumes replay from that intro. Material chapters are selected from the pre-run saved-progress snapshot (completion and best stars only). If Count has no material episode, or Addition has no material chapter/second material chapter, that specific completion/reload branch is marked unexercised with the saved-progress reason rather than manufacturing eligibility or failing an otherwise valid run. No reset, fixture, hidden queue access, answer injection, or made-up reward eligibility is allowed.

## Evidence limits

The JSON reports describe the run and proof boundary. A passed local or canonical run proves only the specified browser journey on the recorded build and retained profile. It does not assert physical-device coverage, all storage backends, or a fresh-user result unless the report independently records that state. Do not replace failed reports or summarize an unexercised fault as tested.

Passive Addition group and bond diagrams must be wholly visible and nonzero-sized; the empty zero group may be40px high. The44px minimum applies to interactive controls, including all active counting objects and answer/Retry/Next buttons. Passive model rectangles are recorded separately and never counted as touch-target violations.
