# Pair 14: Sky Shapes and Monster Math save acceptance

## Purpose and boundary

This source-bound driver checks the live, visible-control journeys for Sky Shapes (`jet`) and Monster Math (`math`) at **390×740** and **1440×844**. The caller supplies the already leased Playwright page. It never creates a browser, tab, context, profile, or page; never resets or seeds app data; never directly writes application records; and never invokes a paid provider. Normal gameplay controls create the accepted progress records. The only permitted origins are `http://127.0.0.1:5180` and `https://dinospace.netlify.app`.

Before acting, the runner checks the matching active lease and exact served module identity, installs provider guards, then navigates the same supplied page to the normal home route, waits for namespaced storage and the player/world chooser, selects Amari when the normal player picker appears, and asserts the exact runtime entry. Provider/API routes are blocked before game interaction; a blocked attempt is a failure. Every recorded control/model is at least 44×44, wholly inside the viewport and center-hit-testable before it is clicked or traced. Primary tasks are never scrolled into view automatically; only world/catalogue and episode-map navigation may scroll.

All game interaction is based on visible copy, rendered models, accessibility labels, and visible SVG paths. No React state, hidden answer coordinates, app-storage mutation, deterministic-run seed, or answer fixture is used. The driver records partial rows and one failure screenshot if an interaction fails.

If no such Sky Shapes cap is reached, the report records the reason and does not alter progress to manufacture eligibility. No incomplete-progress state is seeded. No horizontal overflow, page/console/request/response error, provider attempt, or unexpected changed storage key is accepted.

The optional **390px-only** fault lane wraps `Storage.prototype` for the exact game progress key and, when a naturally earned positive receipt exists, the exact synthetic parent reward key. Original methods are restored in `finally`. It checks Monster Math queue-start write failure and same-run retry; held result local write failure and committed-but-unconfirmed readback; and parent write/readback failures on the first naturally material episode (incomplete or below three stars), preserving the expected new-badge or replay status after retry. A separate parent write fault on the next naturally material episode leaves that receipt pending, then reloads the same page and recognizes either the normal chooser or already-mounted Monster Math intro; startup recovery must confirm the exact receipt and apply exactly one parent delta before the lower replay proceeds. Episode identities are bound to the visible map card and the authored episode enumeration, so existing progress selects the first eligible episode without resetting records. The full Sky lane checks intro queue-start failure, held flight local write/readback failure, and parent write/readback retry while comparing every naturally pending receipt (including a possible chapter bonus). Set `SKY_MONSTER_FAULTS=1` only for explicitly leased 390px native or canonical runs. If no new naturally eligible positive receipt exists for a lane, the report marks that lane unexercised and does not create one.

The full lane records the actual sound preference at the first game intro, enables sound through the visible control for packaged playback, then restores that preference through the visible control before leaving the final game and comparing storage. Pointer and emulated touch traces are reported as authored visible-guide following, not as independent learner mastery. CDP touch emulation is not a physical-device certification.

## Evidence and invocation

The Python runner records stage, viewport, exact module SHA, entry path, current source HEAD and source hashes, QA driver hashes, lease identity, interaction rows, full storage-key hash diff, and bounded HTTP preflight identity. Each run is bounded to one viewport and one browser `run-code` invocation. Python enforces an 8 MiB evidence-directory budget; screenshots are failure-only. Keep only compact JSON reports and unique failure evidence.

Root must supply the existing active lease owner and exact live entry/runtime identity. Example invocation:

```sh
SKY_MONSTER_BROWSER_OWNER=pair14-native \
  python3 docs/qa-evidence/sky-monster-save-20261029/run-sky-monster.py \
  http://127.0.0.1:5180 390 740 /assets/arcade-EXACT.js FROZEN_RUNTIME_SHA
```

To run only the separately bounded Sky pending-receipt preparation, add `SKY_MONSTER_MODE=prepare-sky-pending` and `SKY_MONSTER_FAULTS=1`; it is restricted to the explicitly leased 390×740 local preview or canonical site. This produces setup evidence, not the full acceptance report.

Run `1440 844` separately. `SKY_MONSTER_FAULTS=1` is allowed only for the explicit 390px run. Do not use this driver on a newly created browser session. A missing, expired, or mismatched lease is a hard stop. A failed run remains a failure even if a later rerun passes; preserve its partial report and failure image.
